# UI 개선 방향 — Cashflow(금전출납부) 재구축

> 상태: 단계 1(기획 확정) 산출물 · [PRD.md](./PRD.md)와 쌍을 이룸
> 전제: 모바일 중심 PWA + 데스크톱 보조. UI는 "재현"이 아니라 **개선**한다.

---

## 1. 현행 UX 진단 (개선의 근거)

기존 앱(`src/app/(dashboard)/` 11개 페이지 + 컴포넌트) 분석에서 확인된 문제:

### 1.1 구조·내비게이션
- **모바일 내비가 2탭 거리**: 햄버거 → Sheet → 메뉴 선택. 10개 메뉴가 평면 나열되어 사용 빈도와 무관하게 동일 비중.
- **하단 내비게이션 없음**: 한 손 조작 시 상단 햄버거·상단 버튼까지 엄지가 닿지 않는다.
- **핵심 동선(거래 입력)이 특권화되어 있지 않음**: "새 거래" 버튼이 거래 화면 상단에만 존재. 다른 화면에서 지출을 기록하려면 이동 2회가 선행된다.

### 1.2 거래 입력(가장 자주 쓰는 기능)
- 현행: 버튼 → 중앙 Dialog(`sm:max-w-md max-h-[90vh]` 스크롤) → 유형 탭 → 금액 → 내용 → 계좌 → 저장 = **최소 5~6탭 + 키보드 전환 2회**.
- 계좌·카테고리 기본값 없음(매번 선택), 조건부 필드(할부·저축 이체)가 예고 없이 나타나 인지 부하.
- 저장 후 서버 응답 대기(현행 5초 문제) — 낙관적 업데이트 없음.

### 1.3 일관성·완성도
- 삭제 확인이 네이티브 `confirm()`/`alert()`(transactions, accounts 카드결제)와 커스텀 `DeleteConfirmDialog`(assets, forecast 등)로 혼재.
- 빈 상태에 CTA 버튼이 없는 화면 다수(거래·투자는 텍스트 안내만).
- 터치 타겟: `icon-sm` 버튼(수정/삭제), 월 네비게이터 화살표, 드래그 핸들(4~5px)이 44px 미만.
- 거래 목록이 7컬럼 `<Table>` — 모바일에서 가로 압축·truncate로 판독성 저하.
- 812줄(investments)·632줄(accounts) 단일 페이지 컴포넌트 — 완성도 이전에 유지보수 문제(재구축 시 `src/features/*` 수직 분할로 해소).

### 1.4 시각 디자인
- shadcn 기본값에 가까운 중립 카드 그리드. 색은 이미 의미적으로 쓰이고 있으나(수입 emerald/지출 rose/저축 violet/이체 blue) **토큰화되지 않은 하드코딩 유틸 클래스**로 산재.
- 요약 카드 6개가 동일 크기·동일 강조 — 위계 없음. "이번 달 지출"과 "계좌 수"가 같은 무게.

## 2. 디자인 원칙 (전 화면 공통)

1. **모바일 퍼스트**: 320px에서 설계를 시작하고 데스크톱은 확장으로 취급한다.
2. **터치 타겟 최소 44×44px**: 모든 버튼·행 액션·네비게이터·드래그 핸들. 시각 크기가 작아도 히트 영역은 44px 확보.
3. **엄지 존(thumb zone) 우선**: 빈도 높은 액션은 화면 하단 1/3에 배치한다.
4. **숫자가 주인공**: 금전출납부의 본질은 금액. 타이포 위계의 정점은 항상 금액이다.
5. **색은 의미로만**: 장식 색 금지. 색상 = 거래 유형/증감 의미 전달 수단.
6. **체감 0ms**: 쓰기는 낙관적 업데이트, 읽기는 스켈레톤(레이아웃 시프트 0)으로 즉시성 연출.
7. **네이티브 `confirm()`/`alert()` 전면 금지**: 앱 내 다이얼로그 + undo 토스트로 통일.

## 3. 스타일 방향: **"모던 원장(Modern Ledger)" — 숫자 중심 에디토리얼**

제네릭 대시보드 템플릿(균일 카드 그리드 + 사이드바 + 장식용 액센트 1색)을 금지하고, **종이 원장(장부)의 밀도와 규율을 현대적으로 옮긴 라이트 테마 에디토리얼** 방향을 채택한다.

### 3.1 왜 이 방향인가

- **제품 본질 부합**: 이 앱은 마케팅 대시보드가 아니라 **기록 장부**다. 사용자는 매일 숫자를 적고 훑는다. 필요한 것은 임팩트 있는 히어로가 아니라 (1) 즉시 읽히는 금액 위계, (2) 행 단위 스캔이 빠른 밀도, (3) 유형이 색으로 즉시 구분되는 규칙성이다.
- **기존 자산 승격**: 현행 앱이 이미 갖춘 의미 색상(수입/지출/저축/이체)과 `font-mono` 금액 표기는 올바른 방향이다 — 이를 하드코딩에서 **토큰 시스템으로 승격**하고 전 화면에 일관 적용하는 것이 개선의 핵심.
- **모바일·야외 사용**: 밝은 환경에서 보는 라이트 기본 + 다크 지원. 자동 다크 기본값 채택하지 않음.

### 3.2 구체 규칙

**타이포그래피 — 2단 전략**
- 본문/레이블: `Pretendard Variable`(국문 최적화, variable 1패밀리). UI 텍스트는 13~15px 좁은 범위로 절제.
- **숫자 전용 스케일**: 금액은 `tabular-nums` + 전용 스케일(`--text-amount-hero: 34px / --text-amount-lg: 24px / --text-amount-md: 17px / --text-amount-sm: 15px`)로 본문과 뚜렷이 분리. 원화 기호·"원"은 금액보다 1단계 작고 연하게.
- 위계는 크기 대비로: 화면당 hero 금액은 1개(예: 대시보드 "이번 달 지출", 결산 "순수익"). 나머지는 md 이하.

**색상 — 의미론 시스템 (장식 금지)**
- 표면: 웜 그레이 단계(`oklch` 98/96/92%)로 종이 질감의 켜(layer)를 만든다. 카드 그림자 대신 **표면 단차 + 1px 헤어라인**이 기본, 그림자는 오버레이(시트·다이얼로그)에만.
- 의미 색 4종을 1급 토큰으로: `--color-income`(green 계열), `--color-expense`(red/rose 계열), `--color-saving`(violet 계열), `--color-transfer`(blue 계열). 각각 `-subtle`(배지 배경)·`-fg` 변형 포함.
- 증감 색은 의미 색과 별도 토큰(`--color-gain`/`--color-loss`)으로 분리(투자 화면에서 지출색과 혼동 방지).
- 그 외 액센트 금지. 브랜드 포인트는 잉크 네이비(`--color-ink`) 1색으로 헤더·활성 상태에만.

**레이아웃 리듬 — "요약 → 추이 → 원장" 3단 구조**
- 모든 조회 화면은 동일 리듬을 따른다: ① 상단 요약(큰 숫자 1~3개, 카드 아님 — 여백과 타이포로만 구성), ② 중간 시각화(스파크라인/차트, 접을 수 있음), ③ 하단 원장(리스트/테이블).
- 균일 카드 그리드 금지. 요약 숫자는 **비대칭 배치**(주 지표 1개 크게 + 보조 지표 작게)로 위계를 만든다.
- 모바일 원장은 `<Table>` 금지 → **2줄 리스트 행**(1줄: 설명+유형 배지 / 2줄: 계좌·태그 + 우측 금액), 헤어라인 구분. 데스크톱(≥lg)에서만 컬럼 테이블로 승격.

**모션**
- `transform`/`opacity`만. 낙관적 삽입 행은 배경 하이라이트 페이드(300ms)로 "방금 기록됨"을 알린다.
- 시트 열림 200ms `ease-out-expo`, 금액 카운트업 등 장식 모션 금지. `prefers-reduced-motion` 존중.

## 4. 내비게이션 개편: 하단 탭 바 (모바일)

### 4.1 채택안

모바일(< md)에서 사이드바+햄버거를 **하단 탭 바(5슬롯)**로 교체한다.

```
┌─────────────────────────────────┐
│  홈    거래   [＋]   예산    전체  │
└─────────────────────────────────┘
```

| 슬롯 | 대상 | 근거 |
|---|---|---|
| 홈 | 대시보드 | 확인 빈도 최고 |
| 거래 | 거래 목록/정기거래 | 기록 확인·수정 |
| **＋ (중앙, 강조)** | **빠른 거래 입력 바텀 시트** | 최빈 액션의 특권화 — 어느 화면에서든 1탭 |
| 예산 | 예산 (소진율 = 월중 확인 빈도 높음) | 월중 반복 확인 |
| 전체 | 나머지(결산·계좌·자산·투자·예측·카테고리·보고서·설정) 그리드 시트 | 저빈도 메뉴 격리 |

- 탭 바 높이 56px + safe-area inset, 각 슬롯 터치 타겟 ≥ 44px.
- 데스크톱(≥ md)은 현행 사이드바 유지(접기 포함) + 사이드바에도 "＋ 새 거래" 상시 버튼 추가.

### 4.2 빠른 거래 입력 (최우선 설계 대상)

현행 5~6탭 다이얼로그를 **바텀 시트 2~3탭 흐름**으로 재설계한다.

- 어느 화면에서든: **＋ 탭 → 금액 입력 → 저장 = 최소 2탭 + 금액 타이핑.**
- 시트 구성(위→아래): ① 유형 세그먼트(지출 기본 선택) ② **금액 필드 자동 포커스**(numeric inputmode, 큰 tabular 숫자) ③ **최근/자주 쓴 카테고리 칩 한 줄**(1탭 선택) ④ 계좌(최근 사용 계좌 기본값) ⑤ 날짜(오늘 기본, 어제/그제 퀵 칩) ⑥ "더 입력"(내용·태그·메모·할부)은 접힘 상태.
- 기본값 전략: 마지막 사용 계좌·유형 기억(로컬), 카테고리 칩은 사용 빈도순.
- 저장 즉시 시트 닫힘 + 낙관적 반영 + "기록됨 · 실행취소" 토스트. 연속 입력을 위한 "저장 후 새로 입력" 토글 제공.
- 저축 카테고리 선택 시 입금 계좌 필드가 같은 시트 내에서 확장(도메인 규칙 §PRD 5.1).

## 5. 화면별 개선 포인트 (기존 대비)

| 화면 | 기존 | 개선 |
|---|---|---|
| **대시보드** | 동일 크기 카드 6개, 3개 쿼리 클라이언트 조합 | ① 비대칭 요약: "이번 달 지출"(hero) + 수입·순수익(보조) + 순자산·잔액(2열) ② `get_dashboard` RPC 1왕복 ③ 캘린더는 주간 축약 → 탭 시 월 확장 ④ 계좌 0개 온보딩 CTA |
| **거래** | 7컬럼 테이블, 필터 5개 노출, 삭제 `confirm()`, 빈 상태 CTA 없음 | ① 모바일 2줄 리스트 행 + 일자 그룹 헤더(일 합계 표시) ② 필터는 칩+필터 시트로 축약, 상태를 URL에 유지 ③ 스와이프 액션(수정/삭제) + undo 토스트 ④ 무한 스크롤 ⑤ 빈 상태에 "첫 거래 기록하기" CTA |
| **거래 입력** | 중앙 다이얼로그 5~6탭 | 바텀 시트 2~3탭 흐름(§4.2), 낙관적 업데이트 체감 0ms |
| **계좌/카드** | 카드 결제 `confirm()`/`alert()`, 드래그 핸들 미세, 이자 정보 상시 노출 | ① 그룹 아코디언 + 그룹 소계 ② 카드 결제는 확인 시트(금액·출금계좌 표시) ③ 드래그 핸들 44px, 길게 눌러 정렬 모드 ④ 만기 D-day는 배지, 이자 상세는 확장 시 |
| **카테고리** | 트리 + 드래그, 펼침 상태 미보존 | ① 펼침 상태 localStorage 보존 ② 색·아이콘이 목록에서 즉시 식별되는 스와치 ③ 빈 상태에 기본 세트 생성 CTA |
| **예산** | 인라인 입력 나열, dirty만 버튼 활성으로 표현 | ① 카테고리 행에 "계획 입력 + 실적 진행 바"를 한 행에 결합(입력과 피드백 동시) ② dirty 시 하단 고정 저장 바(모바일 엄지 존) ③ 연간 그리드는 첫 열 고정 가로 스크롤 ④ 예산 없음 → 전월 복사 CTA 우선 |
| **결산** | 얇은 래퍼 + 뷰 컴포넌트, 다건 쿼리 | ① RPC 1왕복 ② "순수익" hero 금액 + 전월 대비 배지 ③ 카테고리 구성은 막대 리스트(도넛보다 스캔 빠름) ④ 월 이동 스와이프 |
| **자산** | 요약 3카드 + 도넛 + 카드 그리드 | ① 총 평가액 hero + 손익 배지 ② 도넛은 범례 리스트와 결합(색-이름-비중 정렬) ③ 상세의 평가 입력 폼을 시트로 이동 |
| **투자** | 812줄 단일 페이지, 모바일 컬럼 숨김(`sr-only`), 중첩 탭 3단 | ① 종목 카드 중심 재구성(보유/매도완료), 매매 기록은 종목 상세 안으로 ② 실현손익·배당 요약을 상단 고정 ③ 매도 초과 수량 사전 검증 에러를 폼 내 표시 |
| **예측** | 시나리오 카드 + 실행 버튼, 결과 로딩 스켈레톤만 | ① 시나리오 가정을 수정하면 자동 재실행(명시 버튼 제거 검토) ② 목표 금액 입력 시 도달 시점을 차트 위 배지로 ③ 예측 실행 중 진행 피드백 |
| **보고서** | 차트 3개 세로 나열 | ① 기간 선택을 세그먼트(6/12/24)로 ② 차트마다 핵심 수치 1개를 텍스트로 병기(차트 없이도 읽힘) ③ 빈 구간 안내 |
| **공통** | 빈 상태 텍스트만, 로딩 스켈레톤 파편화 | 모든 빈 상태에 CTA(PRD §3.11), 스켈레톤은 실제 레이아웃과 동일 골격(CLS 0), 에러는 재시도 버튼 |

## 6. 디자인 토큰 방침 (CSS 변수)

Tailwind 4 `@theme` + CSS 변수로 단일 정의. 하드코딩 유틸(`text-emerald-600` 등) 금지 — 의미 토큰만 사용한다.

```css
:root {
  /* 표면 — 종이 켜 */
  --color-surface: oklch(98% 0.005 90);      /* 페이지 */
  --color-surface-raised: oklch(100% 0 0);   /* 원장/시트 */
  --color-surface-sunken: oklch(95.5% 0.006 90);
```

## 7. 접근성·품질 기준

- 터치 타겟 44×44px 전수(§2), 키보드로 전 기능 도달 가능(드래그 정렬은 키보드 대체 수단 유지 — 현행 dnd-kit KeyboardSensor 계승).
- 색만으로 의미 전달 금지: 유형 배지는 색 + 아이콘 + 레이블 병행(현행 방식 유지·강화).
- 본문 대비 4.5:1 이상, 의미 색 위 텍스트는 `-fg` 변형으로 보장.
- `prefers-reduced-motion` 시 모션 제거, 스와이프 액션은 버튼 대체 수단 병행.
- 검증: Playwright 스크린샷(320/768/1024/1440, 라이트+다크) + axe 자동 검사 + Lighthouse 모바일 90+.
