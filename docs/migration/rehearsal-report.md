### ISA 불일치 원인 분석

파생 잔액 구성: 초기잔액 6,781,647 + 거래 효과 +2,500,000(입금) + 매매 효과 −8,134,737(매수 85건 −74,086,148 / 매도 60건 +65,951,411) = **1,146,910**.

- buy/sell 효과를 net/total 어느 조합으로 바꿔도 저장값 357,810 이 재현되지 않음 → 단순 규약 차이가 아니라 **구 앱의 잔액 즉시 동기화 누락(드리프트)**.
- 일자별 누적 파생 잔액이 특정 시점에 357,810 과 일치한 적도 없음 → 단일 이벤트 누락이 아닌 복수 건 누적으로 추정.
- 참고: 누적 파생 잔액이 음수가 되는 구간이 존재(2026-03-30 −593,149 등) → **ISA 입금 거래 일부가 transactions 에 기록되지 않았을 가능성**. 즉 "거래 이력이 진실"이라는 §0 전제가 이 계좌에서는 약할 수 있음 — 저장값 채택(§6 보정)이 실제 잔액에 더 가까울 수 있다.
- 매매 7건은 account_id 가 NULL(효과 +2,651,691) — 양쪽 모두 잔액에 미반영(정상, 대사 무관).

**→ 사용자 결정 필요(§6)**: 실제 ISA 앱 잔액 확인 후 ①파생값(1,146,910) 채택(기본, 조치 없음) 또는 ②저장값(357,810) 채택 → 보정 거래(expense 789,100원, 컷오버 전일자) 삽입. §6 스크립트로 처리, 삽입 후 §5.2 재검증.

### 보정안 (검증 완료 — 채택 여부 사용자 결정)

`scripts/migration/90_fifo_recompute_proposal.sql`: 매수 로트 remaining 2→0, 매도 realized_gain 0→**−57,400**(= 372,600 수령 − 430,000 원가). 대상 종목 매매가 4건뿐이라 수기 FIFO 재계산으로 검증(TS 레퍼런스 재계산과 동치).

리허설에서 실제 적용해 확인한 결과: 불변식 위반 0건(21/21 PASS), 멱등(재실행 UPDATE 0), '주식' 자산 파생가치 4,254,140 → 3,824,140. 적용 시 건별 이관 충실도 대사(3.1/3.2)는 해당 2건이 의도적 차이로 표시된다. 확인 후 원상복구(TRUNCATE→transform 재실행)했으므로 **현 리허설 DB는 무보정(as-is) 상태**.

**→ 사용자 결정 필요**: 본 이관 시 90_ 스크립트 적용 여부. 미적용 시 유령 2주(430,000원)가 보유 종목·자산가치에 계속 잡힌다. **적용 권장**.

'주식' 불일치는 독립 이슈가 아니라 위 두 이슈의 파생으로 **완전 분해**된다:

```
diff +416,500 = ISA 잔액 드리프트 +789,100 − 유령 주식 이중계상 372,600
legacy 저장값 3,837,640 = 올바른 파생값 3,824,140(FIFO 보정 후)
                        + 유령 2주 이중계상 802,600 (매수 로트 원가 430,000 + 매도 행 잔여 186,300×2)
                        − ISA 드리프트 789,100
```

구 앱은 유령 2주를 매수 로트(원가)와 매도 행 잔여(매도가) **양쪽에서 이중 계상**했다. 자산가치는 신 DB에서 전액 파생(asset_values_v)이므로 별도 보정 대상이 아니며, ISA·FIFO 결정이 끝나면 자동으로 정합된다.
