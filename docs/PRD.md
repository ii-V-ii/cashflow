# PRD — Cashflow(금전출납부) 전면 재구축

> 상태: 단계 1(기획 확정) 산출물 · 브랜치 `rebuild/v2`
> 관련 문서: [UI.md](./UI.md), (예정) ARCHITECTURE.md / API.md / DB.md / MIGRATION.md
> 근거: 승인된 재구축 계획(`curious-orbiting-rocket`), 기존 앱 화면 분석(`src/app/(dashboard)/` 11개 페이지)

---

## 1. 목적과 배경

### 1.1 제품 정의

개인용 금전출납부 웹 앱(PWA). 수입·지출·이체 기록을 중심으로 예산, 결산, 자산, 투자 수익률, 미래 예측까지 하나의 데이터 모델 위에서 제공한다.

### 1.2 재구축 이유

현재 앱은 큰 그림 없이 기능을 덧붙여 개발되어 구조적 성능 문제가 있다.

- **대표 증상**: 거래 저장에 5초 이상 소요 (쓰기 경로 8~12개 순차 DB 왕복 + 광역 캐시 무효화 연쇄)
- **구조 문제**: 파생 상태(잔액·자산가치)를 매 쓰기마다 앱에서 재계산·저장, 800줄대 페이지 컴포넌트, E2E/성능 테스트 부재

재구축의 핵심은 **쓰기 1왕복화 + 파생값의 DB 위임(뷰/RPC) + 세분화된 캐시 전략 + 낙관적 업데이트**다. 기능은 기존 10개 영역을 전부 보존하되, UX는 모바일 퍼스트로 개선한다(UI.md 참조).

### 1.3 성공 지표

| 지표 | 목표 |
|---|---|
| 거래 저장 서버 지연 | **p95 < 500ms** (프로덕션 실측) |
| 거래 저장 체감 지연 | **0ms** (낙관적 업데이트 — 저장 즉시 목록·잔액 반영) |
| Lighthouse (모바일) | **90+** |
| 테스트 커버리지 | **80%+** (단위 + DB 통합 + E2E) |
| 데이터 이관 | 기존 Supabase DB 전량 이관, 4대 대사(건수/잔액/FIFO/결산) 통과 |

---

## 2. 사용자와 사용 환경

- **사용자**: 개인 1인 (본인). 다중 사용자·공유 기능 없음. Supabase 이메일 인증으로 본인만 접근.
- **주 사용 환경**: **모바일 브라우저(PWA 설치)**. 가장 빈번한 행위는 "지출 직후 그 자리에서 거래를 기록"하는 것.
- **부 사용 환경**: 데스크톱 — 월말 결산, 예산 편성, 연간 그리드, 투자 분석 등 "앉아서 보는" 작업.
- **향후**: Android 네이티브 앱이 동일 REST API(`/app/api/v1/**`)를 재사용한다. 따라서 모든 기능은 REST 경유로 동작해야 한다(Server Actions 금지).

## 3. 기능 요구사항 (10개 영역)

> 표기 규칙: 각 항목은 검증 가능한 문장("~할 수 있다", "~된다")으로 작성한다. 각 항목이 그대로 구현 태스크의 수용 기준이 된다.
> 공통 상태 규칙(모든 화면): §3.11 참조.

### 3.1 대시보드 (`/`)

접속 시 첫 화면. **1왕복 RPC(`get_dashboard`)로 화면 전체 데이터를 로드**한다(현행은 3개 쿼리를 클라이언트에서 조합).

**요약 카드**
- 사용자는 순자산(자산 평가액 합계)과 취득원가 대비 평가손익·수익률(%)을 볼 수 있다.
- 사용자는 총 잔액(전 계좌 합계)과 계좌 수를 볼 수 있다. 잔액은 `account_balances_v` 파생값이다.
- 사용자는 당해 연도 투자 수익(실현손익 + 배당 합계)을 볼 수 있다.
- 사용자는 이번 달 수입/지출/순수익을 볼 수 있다. 저축 거래는 지출에 포함된다(§5 도메인 규칙).
- 금액은 양수/음수에 따라 의미 색상(수입=긍정, 지출=부정)으로 표시된다.

**거래 캘린더**
- 사용자는 월 캘린더에서 일자별 수입/지출 합계를 볼 수 있다. 캘린더 집계는 `status='applied'` 거래만 포함한다(pending 제외 — 레거시 동일). pending 거래의 '예정' 배지는 거래 목록 화면에서만 표시한다.
- 사용자는 캘린더의 날짜를 탭하여 해당 일자의 거래 목록을 볼 수 있다.
- 사용자는 이전/다음 달로 이동할 수 있다.

**예산 소진율 위젯**
- 사용자는 이번 달 예산 대비 지출 소진율(전체 + 카테고리별 상위 항목)을 진행 바로 볼 수 있다.
- 이번 달 예산이 없으면 "예산을 만들어보세요" 빈 상태와 예산 화면으로 가는 링크가 표시된다.

**상태 처리**
- 로딩: 카드 영역 스켈레톤. 에러: 재시도 버튼 포함 에러 메시지.
- 데이터 자체가 없는 신규 상태(계좌 0개): 온보딩 안내(계좌 만들기 CTA)가 표시된다.

### 3.2 거래 (`/transactions`)

앱의 핵심 화면. 탭: **전체 | 정기 거래**.

**거래 등록/수정 (최우선 동선 — UI.md의 빠른 입력 참조)**
- 사용자는 수입/지출/이체 거래를 등록할 수 있다. 필수 입력: 유형, 금액, 날짜, 계좌(이체는 출금+입금 계좌), 나머지(카테고리·내용·태그·메모)는 선택.
- 사용자는 지출 거래에 할부 개월수를 지정할 수 있고, 목록에 `n/총개월` 형태로 표기된다.
- 사용자는 태그를 자동완성으로 입력할 수 있다(기존 태그 제안, 새 태그 즉시 생성).
- 카테고리가 `expenseKind='saving'`이면 입금 계좌(`toAccountId`) 지정 필드가 나타나며, 이 거래는 저축으로 표시된다(§5).
- **저장 시 낙관적 업데이트**: 확인 즉시(체감 0ms) 목록에 행이 삽입되고 관련 계좌 잔액이 델타 반영된다. 서버 실패 시 롤백되고 에러 토스트가 표시된다.
- 저장 API는 단일 왕복 RPC(`create_transaction`) 1회 호출이다(태그 upsert 포함, 잔액 UPDATE 없음).
- 사용자는 기존 거래를 수정/삭제할 수 있다. 삭제는 확인 다이얼로그(브라우저 `confirm()` 금지, 앱 내 다이얼로그) 후 실행되며 실행 취소(undo) 토스트를 제공한다.

**목록/필터**
- 사용자는 월 단위로 거래 목록을 조회하고 이전/다음 달로 이동할 수 있다.
- 사용자는 다음 필터를 조합할 수 있다: 유형(수입/지출/이체/저축), 카테고리(대분류), 계좌, 태그(다중), 텍스트 검색(내용·메모).
- 필터·월·페이지 상태는 **URL 쿼리 파라미터로 유지**되어 새로고침·공유·뒤로가기에 안전하다.
- 목록은 페이지네이션(모바일: 무한 스크롤 허용)되며 총 건수가 표시된다.
- 각 행에는 유형 배지(수입/지출/저축/이체 의미 색상), pending 거래의 "예정" 배지, 정기거래 아이콘, 할부 표기, 태그가 표시된다.
- 이체 거래는 `출금계좌 → 입금계좌`로 표시된다.
- 사용자는 현재 필터 조건의 거래를 CSV로 내보낼 수 있다.

**정기 거래 탭**
- 사용자는 정기 거래 규칙(주기·금액·계좌·카테고리·시작/종료일)을 등록/수정/삭제/일시정지할 수 있다.
- 규칙 생성 시 향후 12개월치 pending 거래가 생성되고, 매일 배치(pg_cron) + 접속 시 보정으로 도래분이 applied 처리된다.
- 다음 발생일 계산은 월말 보정 규칙(§5)을 따른다.

**상태 처리**
- 빈 상태: "거래 내역이 없습니다" + **새 거래 등록 CTA 버튼**(현행은 텍스트만 있고 버튼 없음 — 개선).
- 필터 결과 0건과 데이터 자체 0건을 구분해 문구를 달리한다("조건에 맞는 거래가 없습니다 / 필터 초기화").

### 3.3 계좌/카드 (`/accounts`)

**목록/그룹**
- 사용자는 계좌를 유형별 그룹(은행/적금·예금/카드/현금/투자)으로 볼 수 있고 그룹별 소계와 전체 합계를 볼 수 있다.
- 각 계좌의 현재 잔액은 파생값(`account_balances_v` = 초기잔액 + Σ거래효과 + Σ매매효과)으로 표시된다.
- 사용자는 그룹 내에서 계좌를 드래그(모바일: 길게 눌러)로 재정렬할 수 있고 순서가 저장된다.
- 사용자는 계좌를 생성/수정/삭제할 수 있다(삭제는 연결 거래 존재 시 경고).

**카드 계좌**
- 사용자는 카드의 결제일, 한도, 현재 미결제금, 한도 사용률(%)을 볼 수 있다.
- 사용자는 카드에 결제 계좌를 연결하고, "결제" 버튼으로 `결제계좌 → 카드` 이체 거래를 원탭 생성할 수 있다(확인 다이얼로그 포함, 네이티브 `confirm()`/`alert()` 금지).

**예·적금 계좌**
- 사용자는 예금(거치식)/적금(적립식)의 금리, 만기일, 만기까지 D-day를 볼 수 있다.
- 사용자는 세전/세후(일반과세·비과세 등 세금 유형별) 예상 이자를 볼 수 있다. 계산은 검증된 TS 순수 함수(`deposit-calculator`)를 사용한다.

**자산 연결**
- 사용자는 계좌를 자산에 연결/해제할 수 있다(1자산:N계좌). 연결된 자산의 평가액은 계좌 잔액에서 파생된다.

**상태 처리**
- 빈 상태: "계좌가 없습니다" + 계좌 만들기 CTA. 그룹에 계좌가 없으면 해당 그룹은 표시하지 않는다.

### 3.4 카테고리 (`/categories`)

- 사용자는 지출/수입 탭별로 대분류·소분류 2단계 트리를 볼 수 있다.
- 사용자는 카테고리를 생성/수정/삭제할 수 있다: 이름, 아이콘, 색상, (지출) `expenseKind`(일반 소비/저축/투자 등) 지정.
- 대분류 삭제 시 하위 소분류 포함 삭제 경고가 표시된다. 거래가 연결된 카테고리 삭제 시 처리 방침(미분류 이동)을 확인받는다.
- 사용자는 드래그로 카테고리 순서를 바꿀 수 있다.
- 사용자는 카테고리를 비활성화할 수 있고, 비활성 카테고리는 새 거래 입력에는 나타나지 않지만 과거 거래·결산에는 유지된다.
- 빈 상태: "카테고리가 없습니다" + 기본 카테고리 세트 생성 제안 CTA.

### 3.5 예산 (`/budgets`)

탭: **월별 | 연간 그리드 | 연간 개요**.

**월별 예산**
- 사용자는 월별로 카테고리(대분류/소분류)별 계획 금액을 인라인 편집으로 입력하고 저장할 수 있다.
- 수입/소비/저축 구분 합계가 실시간으로 표시된다(저축 = `expenseKind='saving'` 그룹).
- 대분류 합계는 소분류가 있으면 소분류 합, 없으면 대분류 값으로 롤업된다(§5).
- 사용자는 전월 예산을 현재 월로 복사할 수 있다.
- 사용자는 카테고리별 계획 대비 실적(status='applied' 거래 집계)과 소진율을 볼 수 있다.
- 미저장 변경(dirty) 상태가 시각적으로 표시되고, 이탈 시 경고한다.

**연간 그리드**
- 사용자는 12개월 × 카테고리 매트릭스에서 연간 예산을 한 번에 보고 편집할 수 있다(모바일: 가로 스크롤 + 고정 첫 열).

**연간 개요**
- 사용자는 연간 예산 대비 실적 추이 차트를 볼 수 있다.

**상태 처리**
- 해당 월 예산이 없으면 "0원 초기화 그리드 + 전월 복사 CTA"가 표시된다.
- `budgets.total_income/total_expense` 저장 컬럼은 폐지 — 합계는 `budget_totals_v` 뷰 파생(§5 설계 원칙).

### 3.6 결산 (`/settlements`)

탭: **월별 | 연간**. 집계는 RPC(`get_monthly_settlement(y,m)`) 1왕복.

**월별 결산**
- 사용자는 월을 선택해 수입/지출/저축/순수익 합계를 볼 수 있다(applied 거래만, 저축 거래 포함 — §5).
- 사용자는 카테고리별(대분류 롤업) 지출 분석과 구성비를 볼 수 있다.
- 사용자는 계좌별 변동(개시 잔액 → 종료 잔액, 증감)을 볼 수 있다.
- 사용자는 전월 대비 증감(금액·%)을 볼 수 있다.

**연간 결산**
- 사용자는 연도를 선택해 월별 수입/지출/순수익 추이와 연간 합계, 카테고리별 연간 집계를 볼 수 있다.

**상태 처리**
- 거래가 없는 월/연도는 "거래가 없어 결산할 내역이 없습니다" 빈 상태를 표시한다.

### 3.7 자산 (`/assets`, `/assets/[id]`)

**목록**
- 사용자는 자산을 전체/금융/비금융 탭으로 나눠 볼 수 있다.
- 사용자는 자산별 현재 평가액, 취득원가, 평가손익(±%)을 볼 수 있다. 계좌 연결 자산의 평가액은 잔액 파생(`asset_values_v`)이다.
- 사용자는 포트폴리오 구성 도넛 차트(자산 카테고리별 비중)를 볼 수 있다.
- 사용자는 자산을 생성/수정/삭제하고 자산 카테고리를 관리할 수 있다.
- 계좌 미연결 자산(부동산 등 비금융)은 수동 평가액을 입력할 수 있다.

**상세 (`/assets/[id]`)**
- 사용자는 자산의 평가 이력 차트(시계열)를 볼 수 있다.
- 사용자는 평가 이력을 수동 추가/수정/삭제할 수 있다. 자동 스냅샷은 일일 배치(pg_cron)로 기록된다.
- 존재하지 않는 자산 접근 시 "자산을 찾을 수 없습니다" + 목록으로 돌아가기 링크가 표시된다.

**상태 처리**
- 빈 상태: "자산이 없습니다" + 자산 만들기 CTA + 계좌 연결 안내.

### 3.8 투자 (`/investments`)

탭: **매매 기록 | 수익 요약**.

**매매 기록**
- 사용자는 매수/매도/배당 기록을 등록/수정/삭제할 수 있다: 종목(자산), 수량, 단가, 수수료, 세금, 일자.
- 사용자는 자산(종목)별로 필터링할 수 있다.
- 매도 등록 시 **FIFO 로트 매칭**으로 실현손익이 자동 계산되고, 매도 삭제 시 역FIFO로 로트가 복원된다(§5). 처리 는 RPC(`create/delete_investment_trade`) 단일 왕복이다.
- 보유 수량을 초과하는 매도는 저장 전 검증 에러로 거부된다.
- 투자 계좌에 연결된 자산이 없으면 자산 연결 안내 빈 상태가 표시된다.

**수익 요약**
- 사용자는 기간(연도)별 실현손익·배당·수수료·세금 합계를 볼 수 있다.
- 사용자는 종목별 상세를 보유 종목/매도 완료 탭으로 나눠 볼 수 있다: 보유 수량, 평균 단가, 실현손익, 배당 누계. 모든 매매 기록이 누락 없이 집계된다(commit 76da628 회귀 방지).
- 사용자는 연간 월별 수익 요약(월 × 실현손익/배당)을 볼 수 있다. `investment_returns` 수동 테이블은 폐지하고 뷰(`monthly_investment_summary_v`)로 대체한다.

**상태 처리**
- 빈 상태: "매매 기록이 없습니다" + 매매 등록 CTA.

### 3.9 예측 (`/forecast`)

- 사용자는 시나리오(이름, 기간, 가정: 수입 증가율·지출 변동율·인플레이션율)를 생성/삭제할 수 있다.
- 사용자는 시나리오를 선택해 예측을 실행할 수 있고, 결과가 저장되어 재방문 시 다시 볼 수 있다.
- 사용자는 **현금흐름 예측** 차트(월별 수입/지출/누적 현금)를 볼 수 있다.
- 사용자는 **자산 성장 예측** 차트를 볼 수 있고, 목표 금액을 입력하면 **목표 도달 시점**이 차트에 표시된다.
- 예측 알고리즘은 프레임워크 독립 TS 순수 함수(`src/lib/forecast/`)로 유지하고 단위 테스트로 검증한다.
- 빈 상태: "등록된 시나리오가 없습니다" + 새 시나리오 CTA.

### 3.10 보고서 (`/reports`)

- 사용자는 기준 월과 기간(최근 6/12/24개월)을 선택할 수 있다.
- 사용자는 수입/지출 추이 차트(월별 막대+선)를 볼 수 있다.
- 사용자는 선택 월의 카테고리별 지출 도넛 차트(대분류 롤업, 구성비)를 볼 수 있다.
- 사용자는 순자산 추이 차트(자산 평가 스냅샷 시계열)를 볼 수 있다.
- 데이터 없는 구간은 0으로 표시하되, 전체가 비어 있으면 빈 상태 안내를 표시한다.

### 3.11 공통 기능·공통 상태 규칙

**인증**
- 사용자는 Supabase 이메일 인증으로 로그인/로그아웃할 수 있다. 미인증 접근은 로그인 화면으로 리다이렉트된다.
- 모든 테이블에 RLS를 적용한다(단일 사용자라도 defense-in-depth).

**설정 (최소 기능 — UI.md '전체' 탭과 정합)**
- 사용자는 설정 화면에서 테마를 전환할 수 있다(라이트/다크/시스템 연동).
- 사용자는 설정 화면에서 로그아웃할 수 있다.
- 사용자는 설정 화면에서 CSV 내보내기(§3.2 거래 내보내기)로 진입할 수 있다.

**PWA**
- 사용자는 앱을 홈 화면에 설치할 수 있다(manifest + Serwist).
- 정적 자산·조회 데이터는 캐시되어 재방문이 빠르다. **오프라인 쓰기 큐는 범위 제외**(§6) — 오프라인 상태에서 쓰기 시도 시 명확한 안내를 표시한다.

**모든 화면 공통 상태 규칙**
- 로딩: 스켈레톤(레이아웃 시프트 없음, CLS < 0.1). 전면 스피너 금지.
- 에러: 사용자 친화 메시지 + 재시도 액션. 에러 원문은 서버 로그에만.
- 빈 상태: 안내 문구 + **다음 행동 CTA**(등록 버튼/관련 화면 링크)를 반드시 포함한다.
- 변경 성공/실패는 토스트로 피드백한다. 파괴적 액션(삭제)은 앱 내 확인 다이얼로그를 사용한다(네이티브 `confirm()`/`alert()` 전면 금지).

**API 규약**
- 모든 API는 REST(`/app/api/v1/**`), 응답 형식 `{ success: true, data } | { success: false, error: { code, message } }`.
- 모든 입력은 Zod 스키마로 서버측 검증한다.

## 4. 비기능 요구사항

### 4.1 성능

| 항목 | 요구사항 | 검증 방법 |
|---|---|---|
| 거래 저장 지연 | **p95 < 500ms** (서버 왕복, 프로덕션) | E2E 어설션(로컬 50ms / 프로덕션 스모크 500ms), 프로덕션 실측 |
| 저장 체감 지연 | **0ms** — 낙관적 업데이트로 즉시 반영, 실패 시 롤백+토스트 | E2E: 저장 클릭 → 목록 반영까지 프레임 단위 확인 |

| 캐시 무효화 | 저장 성공 시 해당 월 키만 무효화(광역 무효화 금지) | 쿼리 키 팩토리 단위 테스트 |

| CWV | LCP < 2.5s, INP < 200ms, CLS < 0.1 | Lighthouse/CrUX |
| 번들 | 앱 페이지 JS < 300kb gzip, 차트는 dynamic import 유지 | 빌드 분석 |

### 4.2 품질

- 테스트 커버리지 **80% 이상**: 단위(Vitest — 이자 계산·월말 보정·예측·FIFO TS 레퍼런스) + DB 통합(로컬 Supabase — RPC·뷰 블랙박스) + 제약(pgTAP) + E2E(Playwright — 저장→잔액, 결산, 예산, 매도→실현손익).
- FIFO는 TS 레퍼런스 구현과 RPC 결과의 property-based 교차 검증을 유지한다.
- 모든 기능은 TDD(RED→GREEN→REFACTOR)로 구현한다.

### 4.3 신뢰성·보안

- 거래·매매 쓰기는 원자적(RPC 내 단일 트랜잭션)이다. 부분 실패 상태가 남지 않는다.
- 파생값(잔액·자산가치)은 저장하지 않으므로 드리프트가 구조적으로 불가능하다.
- RLS 전 테이블 적용, 시크릿은 환경 변수, 에러 메시지에 내부 정보 비노출.
- 정기거래 배치(pg_cron)는 멱등하게 재실행 가능하다.

### 4.4 호환·접근성

- 모바일 퍼스트 반응형(320px~), 터치 타겟 최소 44×44px(UI.md).
- 키보드 내비게이션, 폼 라벨, `prefers-reduced-motion` 존중.
- 최신 Chrome/Safari(iOS)/Firefox 지원.

### 4.5 통화 처리

- KRW 정수 처리(소수점 없음), DB는 `bigint`.
- 표시 포맷은 `Intl.NumberFormat('ko-KR')` 단일 유틸리티로 통일한다.

## 5. 도메인 규칙 (재구축 시 필수 보존)

아래 규칙은 기존 앱에서 검증된 불변 규칙이다. 위반은 회귀 버그다. 각 규칙에 대응 테스트를 반드시 작성한다.

1. **저축 거래 규칙**: `type='expense'` + `category.expenseKind='saving'` + `toAccountId` 지정 거래는 **예산·결산에 지출로 포함**된다(commit 9c2dffd 회귀 방지). UI에서는 "저축" 유형으로 구분 표시한다.
2. **잔액 규칙**: `income`은 계좌 +, `expense`/`transfer`는 출금계좌(`accountId`) −, `toAccountId`가 있으면 해당 계좌 +. 잔액은 저장하지 않고 `account_balances_v`(초기잔액 + Σ거래효과 + Σ매매효과)로만 파생한다.
3. **투자 FIFO 로트 매칭**: 매도 시 매수 로트를 시간순으로 차감하고 `realized_gain`을 계산한다. 매도 삭제 시 역FIFO로 로트 `remaining_quantity`를 복원한다. FIFO 로트 상태는 파생 금지 원칙의 **유일한 저장 예외**이며 변경은 RPC 내부에서만 일어난다.
4. **정기거래 월말 보정**: 다음 발생일 계산 시 1/31 + 1개월 = 2/28(윤년은 2/29). 말일 기준 규칙과 윤년 처리를 보존한다(`calculateNextDate` 순수 TS 유지).
5. **예산 집계**: 카테고리는 대분류로 롤업(`COALESCE(parent_id, id)`)하고, `status='applied'` 거래만 실적에 집계한다. pending(예정) 거래는 집계 제외.
6. **예·적금 이자 계산**: 거치식/적립식 각각 세전·세후(세금 유형별) 계산 로직을 보존한다(`deposit-calculator` 순수 TS 유지).
7. **카드 로직**: 결제일·한도·미결제금(카드 계좌 음수 잔액의 절대값)·한도 사용률 계산, 결제 계좌 연결 및 원탭 결제(이체 거래 생성)를 보존한다.
8. **통화**: KRW 정수(소수점 금지), 표시 `Intl.NumberFormat('ko-KR')`.
9. **파생 상태 저장 금지(설계 제1원칙)**: 저장은 사실(거래·매매·평가이력·예산 항목)만. 잔액·자산가치·예산합계·결산은 읽기 시점 뷰/RPC로 계산한다. 예외는 규칙 3의 FIFO 로트뿐이다.
10. **정기거래 pending 생성**: 규칙 생성 시 향후 12개월 pending 거래 생성, 도래 시 applied 전환(일일 배치 + 접속 시 온디맨드 보정, 멱등).
11. **배당의 결산 처리**: 배당(dividend)은 `investment_trades`에만 기록되며 `transactions`에 없으므로 **결산(`get_monthly_settlement`)의 총수입에 포함되지 않는다** — 레거시 동작 보존. 배당은 대시보드/투자 요약의 `investment.dividend`로만 표시된다.
